# 逐条审核与发送

2026-10-27 新增需求，扩展版本2.3.0。原始需求文档保留作为历史基线。使用者明确要求：本人逐条确认的这段话术应当成为首次招呼，禁止“先发平台默认招呼、再补发自定义话术”。

## 使用流程

本人关闭BOSS自动招呼 → 启动脚本自动找职位 → 脚本列表初筛、低频读JD并核对薪资及资格 → 未命中就休息后续找 → 命中后生成话术、保留原JD标签并停止 → 本人核对并修改话术 → 记录修改 → 本人逐条确认 → 点击立即沟通 → 核对会话身份及历史为空 → 将确认过的文字作为首次招呼发送一次。

默认由脚本独立发现和筛选职位，无需手动挑选。先排除日薪实习、明确不接受目标毕业年份等条目，再优先读取目标届别和校招的未浏览JD。每轮上限仅统计JD读取；列表初筛不占配额。薪资下限未明确达到门槛的记录保存为待确认，继续查找，不交给用户逐条代筛。

未命中时按已保存的轮次间隔休息后自动继续，单次启动最多6轮；等待期间仍可暂停和停止，后台阻止提前续轮和并行搜索。列表至多初筛100条/轮，连续两次滚动仍没有未浏览结果则结束。自动续找可在配置页关闭。命中薪资明确达标且未被规则或模型跳过的候选就停在JD，并展示资格和技能待确认事项。审核期间不开始新轮次；审核完成后需要本人再次启动新的搜索。

## 确认与发送

确认按钮默认禁用。本人需核对职位和最终文本，并确认已在BOSS“消息通知 → 设置打招呼语”关闭“启用招呼语”。审核面板提供设置页链接，不擅自更改账号设置。改动文本或修改原因会取消当前勾选。点击按钮先保存修改，再绑定职位URL、招聘者、最终文字和草稿版本；授权有效期两分钟，不跨职位复用。

BOSS点击“立即沟通”本身不会代入扩展话术。关闭平台自动招呼后，助手打开会话，再将本人确认的文本填入输入框并点击发送。只识别“立即沟通”，不以“继续沟通”处理旧对话。已有消息、平台默认招呼、历史仍在加载或结构不能识别时均停止；不会补发。助手不点击附件简历发送或交换联系方式。

发送仅通过正常可见的网页控件。新聊天标签必须由本次JD标签打开；在当前会话顶部同时核实原职位链接和招聘者姓名，无法核实则停止。聊天历史、左侧联系人和推荐岗位不作为匹配证据。页面结构不兼容时保留人工处理，不使用私有接口或事件可信度伪装。

新会话至少连续两秒保持没有消息，填写及点击发送前再次核对。输入框已有内容、会话变化、历史出现任何消息、文本不一致、按钮不唯一、登录或验证异常时停止。后台先登记不可重试的首次发送尝试，再点击一次；只有输入框清空且出现对应的本人消息回显时，记录为“页面已发送”，不将其等同于服务器送达或对方已读。旧版补发授权不再恢复。

结果不确定时不会重试或刷新后恢复发送。本条记录保持锁定；本人到BOSS核对后，可刷新JD点击“我已核对BOSS，结束本条审核”，允许继续浏览其他职位，不会解除本条发送锁。

低频和人工审核旨在减少账号风控风险，不能保证不封号。

## 修改记录与隐私

修改和确认记录保存在本机Chrome扩展存储的feedback中，候选及发送状态在records中。记录字段包括职位URL、标题、公司、JD快照、模型原稿、修改前后文字、修改原因、时间、草稿版本、生成时的模型和提示词版本。未修改文字直接确认也会记录一次确认事件；相同文字重复保存不产生无意义记录。

记录不附带整份简历或API Key，但话术自身可能包含本人姓名或经历。通过“导出话术修改记录”手动下载JSON后，可在本机整理用于调优提示词；本版本不会自动训练、上传或把历史修改回传模型。若后续更新提示词，需明确新版本及验证范围。

真实简历文件仍只放local/，Key仅放Chrome配置。local/及话术记录的导出文件名已被Git忽略，提交前仍运行公开文件审计。

## 验证状态

真实JD审核面板已经在已登录Chrome显示，确认框初始未勾选、发送按钮初始禁用。已只读检查BOSS招呼设置页面，并观察到自动招呼开关关闭。隔离测试覆盖首次招呼授权、旧授权拒绝、历史消息与默认招呼阻断、版本变化、会话绑定、重复发送、超时和页面切换，不向BOSS发消息。关闭招呼后实际能否建立空会话、聊天历史DOM是否完整以及首次文字发送，仍需本人批准一个从未沟通过的新职位及具体话术后验证；未验证前不宣称已跑通。
