# 逐条审核与发送

2026-10-27 新增需求，扩展版本2.2.0。原始需求文档保留作为历史基线，本次明确授权增加“本人逐条确认后由助手执行发送”。

## 使用流程

本人打开BOSS搜索页并开始一轮 → 按保存的数量和间隔浏览 → 读JD、筛选并生成话术 → 遇到候选或待确认就保留原JD标签、结束浏览 → 本人核对并修改话术 → 记录修改 → 本人逐条确认 → 点击立即沟通 → 核对会话 → 发送确认过的文字一次。

默认开启遇到候选停止。待确认职位展示薪资、资格和技能缺口，不会被当成完全达标。审核期间不开始新一轮；选择暂不沟通或完成发送后，仍需等冷却结束并手动开始。

## 确认与发送

确认按钮默认禁用。本人需核对职位和最终文本，并勾选包含平台默认招呼提示的确认框。改动文本或修改原因会取消当前勾选。点击按钮先保存修改，再绑定职位URL、招聘者、最终文字和草稿版本；授权有效期两分钟，不跨职位复用。

BOSS“立即沟通”可能先发送默认招呼并展示在线简历；自定义话术可能成为后续消息。助手不修改平台默认招呼、不点击附件简历发送或交换联系方式。

发送仅通过正常可见的网页控件。新聊天标签必须由本次JD标签打开；在当前会话顶部同时核实原职位链接和招聘者姓名，无法核实则停止。聊天历史、左侧联系人和推荐岗位不作为匹配证据。页面结构不兼容时保留人工处理，不使用私有接口或事件可信度伪装。

输入框已有内容、会话变化、文本不一致、按钮不唯一、登录或验证异常时停止。后台先登记不可重试的发送尝试，再点击一次；只有输入框清空且出现对应的本人消息回显时，记录为“页面已发送”，不将其等同于服务器送达或对方已读。

结果不确定时不会重试或刷新后恢复发送。本条记录保持锁定；本人到BOSS核对后，可刷新JD点击“我已核对BOSS，结束本条审核”，允许继续浏览其他职位，不会解除本条发送锁。

低频和人工审核旨在减少账号风控风险，不能保证不封号。

## 修改记录与隐私

修改和确认记录保存在本机Chrome扩展存储的feedback中，候选及发送状态在records中。记录字段包括职位URL、标题、公司、JD快照、模型原稿、修改前后文字、修改原因、时间、草稿版本、生成时的模型和提示词版本。未修改文字直接确认也会记录一次确认事件；相同文字重复保存不产生无意义记录。

记录不附带整份简历或API Key，但话术自身可能包含本人姓名或经历。通过“导出话术修改记录”手动下载JSON后，可在本机整理用于调优提示词；本版本不会自动训练、上传或把历史修改回传模型。若后续更新提示词，需明确新版本及验证范围。

真实简历文件仍只放local/，Key仅放Chrome配置。local/及话术记录的导出文件名已被Git忽略，提交前仍运行公开文件审计。

## 验证状态

真实JD审核面板已经在已登录Chrome显示，确认框初始未勾选、发送按钮初始禁用。隔离测试覆盖授权、版本变化、会话绑定、重复发送、超时和页面切换，不向BOSS发消息。真实发送须等待本人确认具体职位及话术后，再进行一次受控验证。
