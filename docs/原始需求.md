# BOSS 直聘秋招职位筛选助手原始需求

记录日期：2026-10-23  
版本：v1.0  
状态：需求基线，尚未实现

## 背景与目标

用于个人秋招求职，使用者的 BOSS 直聘账号是自用主号。希望减少反复浏览职位、判断匹配度和撰写打招呼话术的工作，同时优先控制账号风险。

核心目标：自动浏览合适职位，筛选薪资与岗位方向，根据每个岗位的 JD 和个人简历生成针对性话术，最终由使用者审核并手动发送。

低频自动操作仍有平台风控风险，不承诺零封号风险，也不存在已验证的平台认可安全频率。

## 已确认的产品流程

手动打开 BOSS 搜索页 → 点击开始 → 少量、低频浏览职位 → 按薪资和 AI 方向筛选 → 读取合适岗位的 JD → 结合简历生成话术 → 展示候选清单，由使用者发送。

## 已确认的技术方向

拉取 [mrcxsy/boss-auto-apply](https://github.com/mrcxsy/boss-auto-apply)，以其为基础改造，不从零开发完整系统。

复用职位读取、关键词筛选、薪资解析、AI 匹配及话术生成能力。移除原版自动沟通、自动发送与事件伪装等不符合本需求的功能，不能仅通过调长原版投递间隔完成改造。

原项目采用 Apache-2.0 许可证，复用时保留相应许可证和声明。开发时应记录实际使用的上游提交版本。

## 功能需求

### 自动浏览与运行控制

- 使用浏览器访问正常可见的职位列表及详情，通过使用者点击开始启动一轮浏览。
- 每轮少量、低频浏览，支持设置浏览数量上限、访问间隔和轮次间休息。
- 支持暂停、停止，并显示运行状态与停止原因。
- 已浏览职位去重，避免重复访问和重复调用模型。
- 先做列表初筛，再打开符合条件的职位详情。
- 遇到验证码、访问限制、登录失效或页面异常，立即停止并提示使用者处理；不自动绕过或持续重试。

### 薪资筛选

- 支持配置最低月薪，优先按职位薪资区间下限判断是否达标。
- 例：门槛为 25K 时，25–40K 通过；15–30K 标记为待确认，不作为明确达标职位。
- 面议、无法解析或缺少薪资的职位列为待确认，不能默认视为达标。
- 月薪、薪资月数和年包分别记录，避免混用；日薪等其他计薪方式单独标记。

### 岗位方向与秋招资格筛选

- 支持 Agent、智能体、算法、AI、大模型等方向的关键词配置。
- 结合 JD 判断实际工作内容，区分 Agent／大模型应用开发与模型训练／算法研究岗位。
- 支持排除关键词，过滤与目标无关的岗位。
- 核对毕业年份、应届要求、校招／社招及经验要求；不明确的信息标记为待确认。
- 支持城市等基础求职条件配置。

### 简历匹配与个性化话术

- 输入个人简历，结合每个职位的 JD 给出匹配理由、技能或经历缺口及建议。
- 按岗位分别生成打招呼话术，供使用者查看、编辑和复制。
- 只使用简历中真实的技能和经历，不编造指标、工作年限、学历或项目成果。
- 用精简 STAR 结构组织证据，突出业务场景、个人动作与真实成果；兼顾 HR 筛选和面试官可深入追问的亮点。
- 模型调用失败时显示失败状态，不自动发送通用兜底话术。

### 候选清单

- 展示公司、岗位、职位链接、城市、薪资原文、岗位方向和秋招资格判断。
- 展示匹配理由、主要缺口、待确认事项和生成的话术。
- 保存本地浏览记录与处理状态，区分已浏览、候选、待确认、已跳过；具体界面可在开发中调整。

## 账号与数据边界

- 不自动点击立即沟通，不自动打招呼、发送简历、回复 HR 或交换联系方式。
- 不调用 BOSS 非公开接口进行职位采集或沟通。
- 不保留事件可信度伪装、风控绕过或验证码绕过逻辑。
- 登录由使用者完成，不导出或上传账号 Cookie、登录凭证。
- 调用外部模型前明确发送的简历及 JD 字段，尽量减少个人敏感信息；本地存储不等于模型调用数据不出本机。

## 首版验收标准

1. 使用者可以在 BOSS 搜索页手动启动和停止少量浏览。
2. 配置的数量上限与访问间隔生效，停止后不继续打开新职位。
3. 能正确区分薪资达标、未达标和待确认，并按配置筛选目标方向。
4. 能读取合适职位的 JD，生成基于真实简历的匹配分析和个性化话术。
5. 候选清单可查看职位详情与复制话术，整个流程不会自动发起沟通或发送消息。
6. 检测到验证码或访问异常后停止，不进行绕过。
7. 已浏览职位能够去重。
